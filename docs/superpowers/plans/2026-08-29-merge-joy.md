# Ashlife Merge & Joy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished, lazy-loaded Ashlife physics merge game with deterministic daily challenges, capped Joy Coin rewards, shared collection progress, and mobile controls.

**Architecture:** React owns the route, HUD, modals, persistence, and reward application; a dynamically imported Phaser Matter scene owns the real-time board. Pure configuration and rules modules sit between them so gameplay, daily selection, scoring, danger timing, and storage migration can be tested without a browser.

**Tech Stack:** React 19, React Router 7, Phaser 3.90 Matter Physics, Node test runner, Vite 5, CSS.

**Spec:** `docs/superpowers/specs/2026-08-29-merge-joy-design.md`

## Global Constraints

- Preserve `ashlife-playroom-v1` and all existing Memory Match, Claw Machine, sticker, wallet, cart, and preference data.
- Lazy-load the route and dynamically import Phaser; no Merge & Joy assets may load on shopping routes.
- Use the 11 required named tiers and final generated raster sprites; no placeholder circles.
- Daily sequences and challenges use the user's local date and never call `Math.random()`.
- Daily Merge & Joy rewards are idempotent and capped at 30 Joy Coins per date.
- Touch layouts must avoid horizontal scrolling at 320 px and keep the board and Drop control reachable.
