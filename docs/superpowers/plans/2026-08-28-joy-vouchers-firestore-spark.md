# Joy Vouchers on Firestore Spark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the undeployable Cloud Functions Joy wallet backend with a Cloud Firestore transaction-based implementation that works on Firebase Spark.

**Architecture:** The Firebase Web SDK writes Joy wallets, idempotent reward claims, and voucher records directly to Firestore. Pure state modules define fixed tier and lifecycle behavior, repository modules execute Firestore transactions, and Security Rules constrain ownership and voucher transitions. Realtime Database remains responsible for products and orders.

**Tech Stack:** React 19, Firebase Web SDK 12, Cloud Firestore Standard, Firebase Authentication, Realtime Database, Node test runner, ESLint, Vite.

**Spec:** `docs/superpowers/specs/2026-08-28-joy-vouchers-firestore-spark-design.md`

## Global Constraints

- Do not require Blaze, Cloud Functions, Cloud Run, Cloud Build, or a payment method.
- Tiers remain 100 coins/RM1/minimum RM10, 200 coins/RM2/minimum RM15, and 500 coins/RM5/minimum RM20.
- Codes use `JOY-RM{value}-` plus ten characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` generated by `crypto.getRandomValues()`.
- Only one voucher applies to an order and delivery is never discounted.
- Reserve at checkout, consume on confirmed/completed, restore on rejected/cancelled.
- Keep existing visual design and anonymous-auth flow.
- Client-manufactured game reward claims are an accepted limitation.
